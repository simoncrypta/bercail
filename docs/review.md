# review

Agents stage their changes and leave them uncommitted. When the desk agent finishes, [tuicr](https://github.com/agavra/tuicr) opens that work so you can read it in the terminal. Comments stay human vs AI, and you choose what gets a GitHub comment.

Review is a tab in the space. Own work → `tuicr -w` (everything uncommitted: staged, unstaged, and untracked; agents stage and never commit unreviewed work); someone else's PR on this checkout → `tuicr pr <n>`. Bercail adds `-w` or `pr <n>` only with `review = "tuicr"` (see [config](config.md)); any other `review` runs as written.

It opens when the desk agent finishes a turn (done, or working → idle) and the checkout has uncommitted changes, the next time you look at that space. A clean tree does not auto-open. `Ctrl+Shift+R` opens it anytime; `auto_review = false` keeps only the key and the agent action. A live Review tab is not restarted: tuicr's diff watch, which bercail turns on, keeps a `-w` review current. A Review tab whose tool has quit opens fresh. An agent opens and closes it with `herdr-app do bercail-desk.review:$HC_TERMINAL_ID` and `bercail-desk.close-review:$HC_TERMINAL_ID`.

The desk mod reads `config.toml` when it loads, so a change to `review` or `auto_review` reaches it after the mod reloads (an app restart does it).

Inside tuicr, `j`/`k` move around. The `review` skill waits for your notes and publishes them to GitHub only when you ask; its helper scripts are listed under [skills](cli.md#skills).

## Someone else's PR: `bercail review-pr`

The code in a teammate's PR was likely written by an agent, and review bots already comment on its lines. `bercail review-pr <PR url-or-branch>` reviews its whole stack by intent and decisions: what each PR is for, the choices it made, which of them nothing explains, and what it promised but didn't do. A single PR is a stack of one.

```bash
bercail review-pr https://github.com/OWNER/REPO/pull/123
```

1. **Discover and gather**: The repo's `git` backend selects discovery: `gt` keeps the Graphite walk in an isolated clone; `gh` uses `gh stack` for a registered stack, otherwise walks GitHub PR bases down to trunk and children up to the top; `origin` uses `origin stack` and `origin pr`. A stray Graphite config alone never selects `gt`. Calling with any PR in the stack resolves the same bottom (root) PR. PR bodies, closing issues, Linear ids (only noted), pinned commit messages, diffs, and `gh pr checks` are gathered. Checks are kept even when gh exits non-zero. Artifacts live in `${XDG_STATE_HOME:-~/.local/state}/bercail/reviews/<host>/<owner>/<repo>/stack-<root>/`, with one `pr-<n>/<head sha>/` per PR head. `stack.json` records order, parent SHAs and the current PR; `stack.md` gives the stack's order, bases and intent. Each PR's diff and commit range are against its parent, not trunk.
2. **Worktree and space**: one detached sibling worktree, such as `~/Work/leftlane_app.review-123`, starts at the root PR. Bercail uses its normal worktree layout helper, so Herdr groups the desk under the reviewed repo rather than creating an unrelated state-directory review space. The main checkout's branch, files, config and other worktrees stay untouched. Graphite synchronization happens only in an isolated clone, never in your checkout.
3. **Thin check**: an empty body, a body that only restates the title, no linked issue (GitHub or Linear), or only "part N of M". The printed JSON lists flags and pass status **per PR**. Thin PRs wait; the rest start immediately. Shep asks only about flagged PRs. `bercail review-pr run N --stack DIR` explicitly reviews one, including a thin PR. `--no-run` gathers without starting any passes.
4. **The decisions passes**: with Herdr open, one read-only Pi session produces the cards on the review space's desk. PR passes queue for that session instead of opening independent agents: the desk takes each pass when it is idle. The reviewer is bstack's `pi/review.json`: the lead's model, the `bstack-pr-review` rules, and only Pi's read, grep, find and ls tools. The session runs in the stack dir, outside the reviewed repo, with immutable, SHA-pinned file context, so moving the worktree cannot change what it reviews, and bstack's `review.ts` extension blocks a read outside that dir. No bug hunting, style, nits, or tests. Validated output becomes `review.json` (`bercail.review/v1`). `run.json` records `ready`, `blocked`, or `failed` with the desk's session id. Per-PR locks prevent duplicate passes. Gathering cannot replace inputs during a live pass. Without Herdr, CLI passes still run headlessly (`pi -p`) in parallel. `bercail update` writes that profile.
5. **The cards**: the Stack tab is bercail's `bercail-review` Herdr mod. The UI needs the Herdr app. Without it `bercail review-pr ui` fails and says so. Each picker row shows the PR title, one truncated code-inferred intent line, then pass status and CI. There is no second PR list. The card has distinct section headings for Inferred intent, Clue comparison, Decisions, Unmet, Description, Questions and CI. Intent shows confidence, evidence and whether it looks like the right thing to build. Each clue shows its source, alignment and comparison. Each decision has separate labeled lines for Kind, Summary, Evidence, Stated, Fit and Alternative. File references and code identifiers use compact, colored monospace chips. Long paths show their basename and line, with the full path on hover. The mod reads `bercail review-pr state` and reloads when the run dir changes. `bercail review-pr ui` shows the tab, or makes it.
6. **Each PR's actions**, by key or by their buttons on the card (**j**/**k** pick a PR):
   - **c Code review**: a `Review #N` tab on `tuicr pr <n>` in the review space (`bercail review-pr open N`). Each question goes in as a draft note by `bstack`, starting `[AI Agent] `, on the decision's line (the whole PR when it has none). Edit, delete, add your own, then `:submit`. One tuicr per review space: the Review tab is made fresh each time (drafts stay in tuicr's session).
   - For Origin, **c Code review** opens `origin pr view --web` instead. The installed tuicr PR mode does not support Origin, so local review cards are not seeded into its browser review.
   - **r Re-review**: gather the stack again (heads, CI, bodies), then run this PR's decisions pass again, even if it was ready (`bercail review-pr rereview N`).
   - **o Shell**: the review worktree on the PR's branch and a `Shell #N` tab in it (`bercail review-pr checkout N`). A missing local branch is made at the PR head. Bercail never moves a branch of yours: when yours is elsewhere, or checked out in another worktree, the worktree goes to the head detached and the tab says why.

The code is the source of truth. The pass reads the diff first and always states a best educated guess of what the change does and is evidently for, with confidence and files/hunks as evidence. It then checks that inference against linked issues (GitHub/Linear), commit messages, and the PR title/body (weakest, often stale AI text). Issues can be loose or sloppy too. Missing or unfetched issues mean no issue clues to compare, not missing intent. GitHub closing issues are fetched; Linear ids alone are recorded, not treated as fetched content.

The card reports where clues agree or diverge: code does more, less or something different; the description is stale; or a comparison is unavailable. It assesses whether the inferred intent looks like the right thing to build, with tradeoffs and uncertainty rather than assuming every issue mismatch is a code mistake. A stale body is a clue comparison, not an author question about the code or an unmet requirement. Decision fit is against the inferred purpose. A body mention alone still does not document a decision; `stated` cites an issue or commit that explains it, otherwise null.

Each card also grades the PR's description (title and body) against the same standard bercail's own `/validate` writes to, the `describe` skill's `standard.md`, which the reviewer gets in its system prompt. Gather copies the repo's PR template from the PR's base, not its head, into `template.md`, so a PR cannot change what it is graded against. The grade is `complete`, `thin` (a part missing: intent, why, how, validation, or risks), or `contradicts` (a claim the diff does not back, shown at its lines). Missing parts and contradictions are separate findings, each with a question for the author that goes into the tuicr drafts. Style is not graded, and the grade never blocks.

New passes save the code-based guess in `why`, use `why_source: "diff"`, and require `intent_analysis` with `confidence`, `evidence`, `clues` and `assessment`, and the `description` grade. The CLI card and native card both show these fields, and the picker uses the inferred summary rather than issue/PR prose. Before a pass completes the card says it awaits code-based inference. Older ready cards remain readable as saved context without fabricated confidence or evidence; Re-review explicitly upgrades them. Viewing the UI never rewrites or reruns them.

The review session is recorded in `desk.json` and runs on the review space's desk; a desk whose Pi quit comes back on the same session. A working desk is never interrupted. Ready cards remain valid when the session changes: opening the UI never reruns a PR. Use Re-review to replace a card explicitly. Desk setup failures leave the saved cards intact, and a busy desk does not prevent viewing them. Thin cards never requested still wait.

When every current card is ready, that same session writes a stack summary: overall purpose, PR order, cross-PR risks and where to look first. It appears above the picker (above the card for a single PR). `summary-input.json` pins its inputs; validated output lives in `stack-summary.json`. A fingerprint includes the actual cards, not just their SHAs, so a changed card hides the old summary until it is regenerated. `bercail review-pr summarize --stack DIR` retries a failed summary without rerunning the cards.

Agents never post. You do, from tuicr's `:submit` or GitHub, and every draft you keep goes out as yours, labelled `[AI Agent]`. In a bstack Pi, `/pr-review <run dir>` runs the same pass by hand.

If no checkout is found, bercail clones to `~/Work/<repo>` (or `~/Work/<owner>-<repo>` if the first path belongs to something else), then creates its sibling review worktree. It never overwrites an existing checkout. A newly cloned GitHub repo without stack metadata uses the generic GitHub walk; a Cursor Origin repo uses Origin's stack discovery.

GitHub CLI reads time out after 60 seconds. Repo cloning and native-stack checkout get five minutes. A timed-out command and its children are stopped rather than holding the review open indefinitely.

If a process is killed during lock recovery, an empty `*.lock.reap` directory can remain and block retries. After confirming no gather, pass or open process is using that stack, remove that empty directory with `rmdir`. Do not remove a live process's lock.

Bercail refuses to reuse an unmarked sibling, or switch a review worktree that has edits or is no longer detached. An interruption between worktree creation and writing its marker can leave an unmarked sibling. Inspect it and remove it with `git worktree remove <path>` before retrying. Do not force removal of user changes.

Refresh after a push is a separate slice. When a stack branches or has ambiguous parents, bercail prints a notice and reviews the requested PR alone. It never chooses a partial path through a fork. Cycles, truncated discovery and API errors still fail.

### Done with a review

```bash
bercail review-pr close https://github.com/OWNER/REPO/pull/123
```

This removes what `review-pr <url>` made for that stack: the sibling worktree, the run dir under `~/.local/state/bercail/reviews/`, and the Herdr space with its desk and Stack tab. Any PR of the stack names it. `close N` works from a checkout of the repo, and plain `close` from the review worktree or with `--stack DIR`.

Close refuses, and removes nothing, while a gather, a pass, the desk's summary or a `review-pr open` is running, and when the worktree has local changes. A commit made on the detached worktree counts as a local change, since it is on no branch. `--force` drops those changes. Files git ignores go with the worktree either way. It only removes a worktree that review-pr made for that stack. Your checkout, its branches (one made by `review-pr checkout` included) and the space you are looking at stay as they are. With the Herdr app closed, or when it cannot list its spaces, the worktree and run dir still go and close tells you to close the space by hand. Closing a stack that is already gone prints `nothing to close` and succeeds.
